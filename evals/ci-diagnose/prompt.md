Use the ci-diagnose skill to diagnose this repository's CI.

This sample repository has no GitHub remote. Its recorded run history is in
`ci-history/runs.jsonl` (the format `measure.py fetch` writes) and the cache
lines from its logs are in `ci-history/cache-lines.txt`: use them in place of
fetching from GitHub. Write your ranked report to `diagnosis.md`, with the
fixes as a numbered list ranked by minutes saved. Don't hand any fix to
another skill; stop after the report.
