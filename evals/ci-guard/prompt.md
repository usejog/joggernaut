Use the ci-guard skill: coding agents write most of this repository's pull
requests, and they push again and again until CI goes green.

This sample repository has no GitHub remote. Its recorded run history is in
`ci-history/runs.jsonl` (each job's steps show which one failed): use it in
place of fetching. Make the changes the skill calls for by editing the files
here (don't commit or push; you can't install packages, so don't run the
tools), and write the pull request description you would open to `PR.md`.
